# 当代人工智能实验二：搜索算法 (Search Lab)

## 1. 环境与依赖

- **适用平台**：Windows / macOS / Linux 均可运行，无平台相关代码。
- **环境要求**：Python 3.9 及以上。
- **依赖说明**：
  - 核心算法模块（`src/`）与测试（`tests/`）仅使用 Python 标准库，零第三方依赖，克隆后可直接运行。
  - 只有 `scripts/` 下的实验脚本在生成图表时需要 `matplotlib`；未安装时脚本自动降级为仅产出数据（见第 6 节）。

安装绘图依赖：

```bash
pip install matplotlib
```

## 2. 数据与目录

本项目不需要任何外部数据集输入。所有地图、博弈树与测试用例均在代码中硬编码；拓展实验中的随机地图由固定种子的伪随机数在运行时动态生成，结果可复现。

完整目录结构如下：

```text
search-lab/
├── .gitignore                        # 忽略 __pycache__/ 与 *.pyc，放行 png 与 metrics.csv
├── README.md                         # 项目说明文档（本文件）：环境、目录、运行顺序与实验配置
├── src/                              # 核心算法实现（纯标准库）
│   ├── __init__.py                   # 包标记，无逻辑
│   ├── astar.py                      # 通用 A* 引擎：堆元素 (f,h,r,c,g)、四计数口径、可重开与启发函数参数
│   ├── q1_maze.py                    # 题目一入口：迷宫寻路，单位代价调用通用 A*
│   ├── q2_weighted.py                # 题目二入口：加权地形最短路，终点进入代价为 0，无解返回 -1
│   ├── q3_alphabeta.py               # 题目三：静态博弈树 Alpha-Beta 剪枝，统计 nodes/leaves/cutoffs
│   └── q4_treasure.py                # 题目四：宝藏分配博弈，六点距离矩阵 + Minimax/Alpha-Beta 交叉校验
├── tests/
│   └── test_public_cases.py          # 15 条 unittest 断言：公开用例 + 边界（起点即终点、无解、覆盖代价等）
├── scripts/                          # 实验运行与相关证据图片产出脚本
│   ├── reporting.py                  # 统一绘图样式与配色、caption 收集、metrics.csv 写入器（列与单位校验）
│   ├── run_experiments.py            # 规定动作 Q1-Q4 入口：运行实验、落盘指标、生成图表与 report snapshot 块
│   └── extensions.py                 # 拓展实验 A/B/C/K：不一致启发、耗时对照、代价敏感性、不可采纳启发
└── report_assets/                    # 运行脚本后自动生成的实验产出
    ├── metrics.csv                   # 全部实验指标数据表，固定 8 列 Schema
    └── figures/                      # 含10 张报告用 png 图（p2_ / p3_ / p4_ / p5_ 前缀对应报告页码）
```

## 3. 运行顺序

按"先验证正确性，再跑实验出图"的顺序执行。

> **注：请确保终端当前路径处于 `search-lab/` 根目录下执行以下命令。**
> （因为 `test_public_cases.py` 依赖项目根目录的模块导入路径，如果在 `tests/` 文件夹内直接执行会报错。）

**第一步：验证算法正确性。** 运行单元测试，确认真理值：

```bash
python -m unittest discover -s tests -v
```

预期输出 15 条测试全部通过，结尾为 `OK`。

**第二步：复现实验数据与图表。** 运行全量实验脚本：

```bash
python scripts/run_experiments.py
```

该命令重新生成 `report_assets/metrics.csv` 与 `report_assets/figures/` 下全部 10 张图，并在终端末尾打印图注候选（`--- captions ---`）与报告抄数用的数据块（`--- report snapshot ---`）。

## 4. 实验配置

- **核心算法架构设计**
  - **A\* 引擎（`src/astar.py`）**：为了避免重复实现搜索逻辑，A* 被封装为一个独立的通用模块。通过传入 `passable`（通行判定）与 `enter_cost`（进入代价）函数，引擎无需关心具体的网格结构。Q1、Q2 以及 Q4 的两两寻路均直接复用了该模块。优先队列中存储 `(f, h, r, c, g)` 五元组，以坐标 `(r, c)` 作为 tie-breaker，确保堆排序的稳定性。返回结果 `AStarResult` 包含路径、总代价以及四个搜索过程指标（`pops`、`expanded_unique`、`closed_skips`、`reopens`），以供后续性能分析。
  - **Alpha-Beta 剪枝**：题目三为静态显式树（直接遍历 `TreeNode.children`），题目四为需要动态更新坐标与剩余宝藏状态（`Q4State`）的隐式博弈树，两者状态结构差异明显，因此未做抽象合并，而是分别独立实现在 `q3_alphabeta.py` 与 `q4_treasure.py` 中。二者状态推进方式不同，但均基于相同的 `alpha >= beta` 截断语义，并通过独立的 `stats` 对象记录访问节点数与剪枝次数，以便进行深度与算法间的效率对比。

- **Q1 & Q2：启发函数配置**
  - Q1 对比了 `h=0`（等价于 Dijkstra，无信息搜索）与标准曼哈顿距离。
  - Q2 的终点 E 进入代价为 0，曼哈顿距离在终点邻格会高估 1，严格来说不再可采纳。因此额外引入修正启发式 `h_adm = max(0, manhattan - 1)` 保证严格可采纳性，并与原始曼哈顿进行扩展节点数的对比。

- **Q3：子节点访问顺序配置**
  - 固定树结构与叶子值，配置了三种子节点遍历顺序：原序（original）、按子树值升序（asc）和降序（desc），以观察节点排序对 Alpha-Beta 剪枝效率的真实影响。

- **Q4：博弈树与距离矩阵配置**
  - 距离矩阵采用 6×6 全联通矩阵，所有两两寻路均调用通用 A*，且 A/B/T 的进入代价统一设定为 1。
  - 搜索深度 H 覆盖 1 到 4。H=4 时刚好取完四个宝藏，为完整博弈；H=1~3 为深度截断，用于观察评估偏差。
  
- **自设对照实验（位于 `scripts/extensions.py`）**
  为探明算法的边界条件与理论性质，设置以下四组对照实验：
  - **实验 A（一致性边界）**：7×7 随机网格（障碍概率 0.30），固定遍历 seed 0~99。使用奇偶扰动启发式（可采纳但不一致），探测 `allow_reopen=False` 是否会导致次优解。
  - **实验 B（计时噪声）**：在 Q1 地图上运行 A*，使用 30 组 × 每组 1000 次测量，组内执行预热与关闭垃圾回收，取组均值与 IQR，旨在界定小实例下耗时指标的测量误差边界。
  - **实验 C（矩阵有向性）**：通过坐标级覆盖，将 T3 的进入代价从 1 改为 3。用于验证"距离矩阵对称仅是代价归一化的巧合，而非模型本质性质"。
  - **实验 K（不可采纳启发）**：在 Q2 地图上放大曼哈顿距离（乘数 k = 1,2,3,5），使其不可采纳，观察代价劣化程度，并与实验 A 的潜在失效机制（可采纳但不一致，实测未触发次优）形成对照。

## 6. 复现与限制

- **核验方法**：单元测试终端输出 `OK` 即表示 15 条断言全部通过，核心算法逻辑与公开答案一致。
- **计时指标的局限**：题目实例规模很小，毫秒级耗时受系统负载与解释器状态影响明显，两次运行的数值会有波动。搜索效率的主结论一律基于确定性指标（扩展节点数、访问节点数、剪枝次数），耗时仅作辅助佐证。
- **零结果的合理性**：拓展实验 A 使用可采纳但不一致的奇偶扰动启发式，探测 `allow_reopen` 开关对结果的影响。在 seed 0–99 中，43 个种子因起点不连通被跳过，其余 57 个连通种子的代价分歧数为 0，触发率为 0 是该地图族下的真实实验结论，并非代码报错；对应柱状图全为零属预期表现。
- **可能出现的降级**：若环境未安装 `matplotlib`，脚本会打印跳过提示，仅生成 `metrics.csv` 而不产出图片，程序不会中断；安装依赖后重跑即可补齐图表。
